## 路线、障碍与视频

路线约45m：[0,6]→[0,7]→[-8,7]→[-8,27]→[-13,27]→[-13,16]。实测北侧既有货架通道内15.51m、相邻通道内8.34m，绕过货架端部。A在[-8,16]、估计y>12时行进中触发；B在[-8,22]、估计y>18触发。B是部分占道，侧向旁路仍存在，不是完全拓扑封路。

原有大货架来自NVIDIA full_warehouse资产；新增A/B由dynamic_fixture.py在运行时组合USD Cube：A为木托盘+四箱，B为立柱+三层小货架，均有真实碰撞。不是外部下载的箱子/推车资产，不预写动态障碍到先验地图，不读真值触发，不瞬移机器人。代价地图记录显示A/B位置初始max_cost=0，出现后max_cost=100，真实扫描进入实时障碍层。

A占地约0.65×0.72m，车体新占地约0.49×0.40m。为放大车留旁路，B跨度由原尺寸录像的2m改1.5m，触发距离也提前；两种视频不可作为同条件公平算法对照。PPO与DWB正式比较应使用同一ROBOT_VARIANT/障碍/速度限制。

成片`JetBot_3x_Rack_Aisles_AB_4x.mp4`：约15.7秒、1280×720、H.264/25fps、按仿真时钟4倍速，无箭头/轨迹/文字叠加。A/B在成片4.77/6.75秒出现。大小10,287,476B，SHA256 `0baad0af4ad57f455c2939d669381dd8fabb720b87312e12592b21972088b61f`。视频作为GitHub Release资产，不放Git大文件。保留固定高度、平滑航向/位置、3度死区与.4rad/s镜头转速上限，观察视线检查0遮挡、最短后距2.4m；完整解码与转角连续抽帧通过。抽帧不等于人工观看整片。

## 缩放实现与边界

只在新case的USD层加入统一scale并同步出生高度；不覆写同学源场景。显式质量按scale^3、显式正惯量按scale^5缩放；零惯量继续由物理引擎根据形状计算。角关节上限保持源值。控制器、桥接、最终速度门共用CASE.json.motion_limits中的轮径/轮距和限速；相机/IMU/LiDAR的米制外参平移随scale缩放、旋转和RGB光学定义保留。代码默认robot_scale=1，仍是原版参数。

放大后雷达看见车体自身几何。只在放大变体对自己的13个USD mesh在chassis米制坐标中的AABB做5mm裕量自过滤；不是按环境物体ID或世界位置屏蔽近物，也不把空缺回波填成自由空间。AABB是保守自身网格体积近似，不是精确三角网格碰撞判定。上轮真实捕获点云的离线检查：2464个近体点全部去除，总去除数也为2464，其余环境点保留。最终53累计自回波1424412条，实际障碍仍可见并触发代价地图/避障。

PPO/视觉接口仍按导航侧交付，不实现同学算法。放大模型必须读取当前CASE/ROBOT_VARIANT；不固定0.37m/s或原轮距，也不宣称原尺寸PPO checkpoint可直接复用。原尺寸RGB-D/命名任务接口47的历史验收独立保留。

## 保留的失败试跑

- 48：XformCommonAPI不兼容原orient操作，缩放未生效；尺寸检查发现后停止，不能称放大成功。之后直接处理有序XformOps并加断言。
- 49：尺寸正确，但车体自身回波触发预测净距保护，未完成导航。
- 50：尝试renderer object IDs自过滤；本运行环境返回全0，过滤无效，导航失败。参考[NVIDIA关于4.5对象ID问题的讨论](https://forums.developer.nvidia.com/t/missing-object-id-information-from-rtx-lidar-omnigraph-node-rtxsensorcpuisaacreadrtxlidardata/327961)，实际修复依据本项目数据与自身网格，不升级/重装软件。
- 51：自身回波过滤后可运动，但1m/s接近A时预测中心净距0.358m低于0.40m保护，停车后未进展失败。未降低保护阈值；改为规划与保护一致、障碍提前出现、速度0.8m/s。
- 52：大转弯最近距中间路点0.614m，超原0.60m半径，旧点未移除导致未进展失败。放大变体中间路点范围改0.80m，终点XY阈值仍0.10m；最终53通过。
