# JetBot终点偏差：分解、修正与复测

用户指出A/B案例20的0.491749m参考终点误差过大，本轮优先处理，不直接将到达容差收紧来掩盖全局定位偏差。保持纯仿真、原生IMU、固定FAST-LIVO二进制、唯一odom/TF/速度门，不给算法输入真值，不推GitHub。

离线诊断使用同一时间戳插值参考轨迹，不做轨迹或终点拟合。20原生动作终点估计误差0.173309m，实际同时间误差0.491578m；AMCL导航位姿相对参考的偏差为[+0.012883,+0.578170]m，范数0.578314m。原生LIVO在声明起点坐标系(平移[0,6]、yaw0，非拟合)的同时间参考误差0.073052m。更早15也出现AMCL约0.277m偏差，而LIVO终点约0.036m偏差。故误差主要在全局定位侧，不能把0.49m全部称为控制停车误差。

20保存的3组原生scan在参考位姿处与CAD占据地图的平均最近距离约2.4/2.4/3.4cm，平移/小角度离线匹配改进量约2–7cm。该小样本不足以认证全程地图，但不支持整体半米的固定地图错位；不据此向运行时添加真值补偿或终点偏移。

案例21：同一A/B原生多目标路线及原速度/原XY0.20m、yaw0.30rad目标容差。只改AMCL初始化：已知CAD配置起点，初始XY协方差从0.04改为0.0025m²，yaw从0.04改为0.0004rad²；Omni运动噪声alpha1–5从0.1降为0.005，检验原设置是否对较准LIVO引入过多漂移。这是受控参数试验，不预先声称通过。参考真值只用于结束后评估。

新增diagnose_endpoint.py只允许RUNNER_RESULT已存在的案例，分解定位偏差、内部估计目标距离与实际误差，输出脚本SHA，并明确里程计全局坐标的起点假设。它不会被仿真/导航/控制导入。

## 21：先修定位，不收紧终点

21同A/B路线原生状态4/SUCCEEDED。原终点XY0.20m设置保持，终点内部估计剩余0.187009m，实际参考0.225332m；同时间戳AMCL导航定位偏差0.045079m，LIVO在声明起点系参考误差0.065601m。相对20定位偏差由0.578314降至0.045079m，实际目标距离由0.491749降至0.225332m。此单次对比支持初始化/运动噪声是主要因素，不能只凭一次就声称普适统计精度。

参考路程12.281621m，A/B均行进中触发，按0.16m圆形近似余量0.384774/0.259437m。速度门与odom无故障，六项输入检查通过，修后的审计器audit_error=null且正常响应关闭；全部12个子进程exit0。未重装、未改原生IMU/FAST-LIVO/原保护阈值。

## 22：独立验证更小的最终控制余量

21定位误差缩小后，22保持相同A/B路线、速度、已知起点初始化和AMCL噪声，只将最终XY容差从0.20收紧至0.10m，DWB同名阈值匹配。Yaw仍0.30rad，中间经过点仍0.60m。已完成，原生状态4/SUCCEEDED；以结束后实际参考共同判定，不能只看内部目标距离。

## 22最终结果

同A/B路线实际参考路程12.644328m，实际参考终点[-9.904173,1.928675]，目标[-10,2]，实际误差0.119457m；比20的0.491749m减少约75.7%。内部估计目标距离0.058212m，不把这个值当实际精度。终点同时间AMCL导航定位偏差0.093938m；LIVO在声明配置起点系参考误差0.016841m，未使用拟合或真值补偿。

原生多目标状态4/SUCCEEDED，A/B均行进中触发并绕过，按0.16m圆形近似的参考余量0.411636/0.477563m，原保护阈值保持。六项输入/TF检查全过，audit_error=null，底盘/估计/速度门无故障、最后DISARMED，全部12个子进程exit0。IMU14312、原生点云579、RGB597、估计odom3263、原生滤波更新1185条；发布者仍唯一，未订阅真值。21与22分别独立重启运行，未重装环境或改固定FAST-LIVO二进制。

|---|---|---:|---:|---:|

这说明本次修正解决了明显的定位侧退化，并改善最终落点；样本不支持“所有路线恒为12cm”或精密停靠认证。当前初始化适用于已知配置起点，不能将它未经调整用于未知起点的全局重定位。下一主线可在此基础推进更长仓库路线，保持每例独立冻结及误差分解。
