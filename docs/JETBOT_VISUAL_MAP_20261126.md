## 双方职责

视觉输出物体类别、置信度、图像采集时刻、map 坐标中的二维观测点和跟踪 ID。深度/雷达给出的点通常位于可见表面，不是物体中心；单个二维图像框不能可靠提供完整平面尺寸。视觉同学无需虚填三维尺寸或朝向兼容旧真值接口。

导航侧负责适配二维观测、多帧关联、地图记忆与过期、目标查询、接近点和 Nav2 检查。本次改造发生在导航侧；旧 oracle 模式仍保留用于历史对照，新 vision 模式不启动它，也不读取其对象 ID、尺寸、货架排号或固定目标绑定。

需要视觉侧提供 `obstacles_best.pt`、SHA256、类别表（含顺序）、推理版本以及训练/验证说明。当前约定类别为 shelf、wall、box、pallet、barrier、cart、sign、person。检测存在叉车被误识别为托盘的已知现象；多帧确认只能降低偶发噪声，不能证明类别正确。

## 数据链路

```text
RGB + 同帧对齐深度 + scan + 采集时刻估计 TF
  -> 队友 PerceptionNode
  -> /perception/objects_2d
  -> vision_mapper
  -> /semantic/objects/visual_map
  -> 任务管理器二维查询与接近点预览
```

`SEMANTIC_OBJECTS.json` 保存当前可查询对象；`SEMANTIC_MAP.json` 保存本会话已确认的历史测量点假设，过期项标记 stale，不能直接作为导航输入。`visual_observations.jsonl` 保留全部接收测量和采集时刻的观察位置。地图坐标来自 FAST-LIVO2 + AMCL 的 TF，未使用机器人真值。

新地图协议是 `jetbot.visual_object_map`，每项保留 `position_xy`、`position_reference=visible_surface`、`geometry=measured_point`、`observed_from_xy`、`last_seen` 和不确定度保护余量，不提供虚构的中心、包围盒、尺寸或朝向。地图 ID 是会话内的空间关联假设，不是永久物理实例 ID。跟踪丢失且长时间未观测后可能建立新的假设；历史层不能拿来统计唯一物体总数。

合并 PR #9 后，导航对象地图使用独立话题 `/semantic/objects/visual_map`；视觉模块自己的5秒缓存仍为 `/semantic/objects/map_2d`，协议为 `atongmu.planar_map`。旧云端03接口检查曾用后者名称；新配置生成器使用新名称，避免不同协议同名发布。集成 supervisor 只启动视觉检测节点和导航 mapper，不重复启动队友的缓存节点。

地图默认仅融合置信度至少 0.65 的可见表面点，同类别空间关联门限 0.45m，至少 3 次且跨度至少 0.3 仿真秒才确认。5 秒内为 active，此后为短期 memory；45 仿真秒或90墙钟秒过期，目标从查询输入移除。历史层最多保留4096项，原始测量日志保留。0.25m 起始不确定度只是未标定的保护余量，不是已测定位精度。person/cart 不固化进本版静态层，地面约束估计点和低置信观测保留在原始日志但不进入静态层。

相机重启更换 session 后清空旧会话对象，拒绝旧 session 延迟包；时钟回退后清空并锁定，必须重启地图会话。map TF 缺失时有界等待采集时刻的 TF，不用最新 TF 补位。

## 语言查询与导航边界

复用已有中文模型的语言分类头提取类别、最近/最远和参照排号。旧对象选择网络依赖完整盒子特征，本次不伪造输入；二维选择使用已确认观测点和明确的欧氏距离。最近/最远指可见表面测量点，不等于物体中心或最短可达路径距离。

尚未建立视觉货架行列身份，出现“第二排货架旁”等指令时返回 REFERENCE_NOT_FOUND，不能沿用 USD 排号假装视觉关系已经完成。单只货架的不同可见面也可能形成多个空间假设，因此本版不承诺完整仓储实例计数或跨视角重识别。

候选接近点仅在已观测一侧，与测量点保持机器人规划半径、padding、现有接近余量及视觉保护余量之和。继续经过原生代价地图、路径、扫描和安全门；视觉点不能替代完整碰撞轮廓。旧真值对象的固定 ID/接近点绑定禁止直接套到视觉地图。本版默认只预览，未自动开放相机识别目标的运动执行。

定位、Nav2、速度门、到达容差及机器人半径仍沿用既有配置；仅新视觉配置开启对齐深度，先无录像联调。语义层不写入先验占据地图或 Nav2 障碍层。

## 部署入口

`tools/make_visual_map_config.py` 从已有导航配置生成独立视觉配置、ROS 参数和输入摘要，要求提供存在的权重、视觉 Python 和语言模型，不会自动下载替代权重。

在云端 admin 环境、同一兼容的 Python 下运行 `tools/check_visual_map_resources.py --weights ABSOLUTE_MODEL_PATH --output NEW_REPORT.json`，检查 ROS、图像桥、推理依赖、实际模型和类别表。目录及报告必须使用新名字；先通过只读预检再运行 `manage_jetbot.sh start NEW_CASE_ID ...`。未收到模型前，不执行启动命令。
