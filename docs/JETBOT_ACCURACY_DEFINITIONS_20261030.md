# 2026-10-30 精度口径纠正与导航参数冻结范围

用户最新明确：任权伟本轮只负责导航/定位参数冻结，场景种子和物体清单不在工作范围，不再推进。到达容差不继续压小；1cm候选不采用。之前只按终点误差筛参数的评价不完整，需增加全程全局定位指标。

## 三种量必须分开

1. 全局定位误差：同一时刻、同一声明地图坐标中，估计车体位姿与离线真值的差。统计位置RMSE、P95、最大值，以及包角后的航向误差。这里应优先对应导师转述的“定位3cm、角度1–2°”；具体是RMSE、P95还是上限仍需明确，不能替导师认定。
2. 真实到点误差：导航结束/停车后，真实车体位姿与指定目标位姿的差。包括定位与控制影响，不等同于定位误差。
3. 到达容差：GoalChecker在估计位姿上判定任务完成的阈值，不是传感器精度、全局定位精度或真实停车保证。

向量关系：true-goal = (estimate-goal) - (estimate-true)。模长不能直接相加，定位偏差与控制残差也可能部分抵消。

## 用现有数据直接核对AMCL

新evaluate_localization_accuracy.py读取localization_probe中的原始/amcl_pose，按消息自己的扫描时间戳去重，与该时刻真值位置/包角航向比较。只取导航反馈覆盖的共同时间窗，不按probe接收时刻比较、不把最后一个amcl_pose当当前位姿、不做全轨迹拟合。

probe约5Hz，可能漏掉AMCL发布；下表是所记录AMCL更新样本的统计，不冒充所有更新或时间加权统计。另以导航全局位姿反馈按.05s统一时间网格独立评估，反映map→odom与估计odom组合后给导航使用的全局位姿。坐标对应沿用声明的CAD/map基准。

## 能否归因为AMCL

已确认全局定位链存在实际误差，而且直接/amcl_pose也有厘米级偏差；终点72在同一反馈时刻估计残差2.95cm、全局定位偏差5.12cm、真实目标误差7.34cm，停车后7.32cm。
但不能据此把根因定为AMCL算法自身。AMCL结果还受先验CAD几何、scan高度/时间/畸变、外参、odom输入和TF一致性影响。更准确的表述是“AMCL全局定位链需要优化”，没有绑架恢复证据，不称“全局重定位失败”。上述表格是历史对照；最终参数及回归见 [导航参数说明](JETBOT_NAV_PARAMETERS_20261030.md)。

FAST-LIVO在声明起点下的局部/相对轨迹误差也与AMCL全局误差不同，不能拿单条离线相对RMSE1.49cm直接承诺全局定位1.49cm。

## 冻结原则

- 分开评价全程全局定位、估计到达判据、真实停车误差、重复成功率和安全保护；不用一项指标替代其他项。
- 不再缩小到达容差；排除1cm候选。3cm历史值保留作对照；最终配置固定5cm、.05rad（约2.86°）并单独验证停车稳定性。角度容差按实际终点对准需求选，不为证明定位航向精度而追求极小阈值。
- 不把全程全局误差RMSE直接设为GoalChecker容差：系统偏差与短时抖动不同。需根据终点估计抖动、可执行速度/控制周期、重复到达稳定性与实际任务要求选择。
- 参数冻结依据全程定位统计和A/B/C重复回归；当前少量试验不能最终定优。优先使用现有证据补齐指标，再做有针对性的参数比较。
